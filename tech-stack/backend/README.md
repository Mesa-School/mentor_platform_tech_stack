# backend-service — Node.js + TypeScript API boilerplate

Production-grade API skeleton. **Infrastructure only** — no features are implemented.
Everything a service needs before the first endpoint exists is wired up; the first feature goes
in `src/modules/` by copying `_template/`.

Start by naming it — see [Renaming this service](#renaming-this-service). Nothing user-visible
is hardcoded, so it takes two environment variables and one line in `package.json`.

## Stack

| Concern | Choice | Why |
|---|---|---|
| Runtime | Node 20+, TypeScript strict, **ESM** (`NodeNext`) | `tsx` for dev, `tsc` for build |
| HTTP | **Express 5** + helmet, cors, express-rate-limit | Express 5 forwards async rejections to the error handler automatically |
| Schema & migrations | **Prisma Migrate** — DDL only | Best-in-class migration DX, declarative schema |
| Queries | **Kysely** over `pg` — types generated by `prisma-kysely` | Hand-written, fully typed SQL. The Prisma Client is never imported at runtime, so there is **no ORM** |
| Validation | **Zod** — request input *and* env config | One mental model; bad env crashes at boot, not at 3am |
| Auth | Self-issued **JWT** (jose), access + rotating refresh, **argon2** hashing | Role and department in the claims — no DB hit on the hot path |
| Authorization | RBAC middleware + data-scope guards applied **in SQL** | Scoping in `WHERE` is both secure and fast |
| Logging | **pino** + `pino-http`, request-id correlation, secret redaction | Structured, queryable, low overhead |
| Errors | Typed `AppError` hierarchy → one central handler | Predictable codes; internals never leak |
| Docs | **OpenAPI 3.1 generated from the Zod schemas** — Swagger UI + Redoc | The docs cannot drift from the validation |
| Tests | **Vitest** + supertest against a dockerized Postgres | Real SQL, real constraints |

## Getting started

```bash
cp .env.example .env
npm run prepare:env     # prints a secret — run twice, one per JWT_* variable
npm install
docker compose up -d    # Postgres 16 on :5432, plus the app_test database the tests need
npm run db:migrate      # applies the baseline migration, regenerates src/core/db/types.ts
npm run dev             # http://localhost:4000
```

Set `SERVICE_NAME` and `SERVICE_DESCRIPTION` in `.env` before the first run — they are what the
landing page and the docs display.

`.env` is git-ignored. `npm run dev` loads it via Node's `--env-file`; in production the
platform injects the environment and `npm start` reads it directly. For a **managed** Postgres,
put the full URL in `DATABASE_URL` and set `DB_SSL=require` (see [Database TLS](#database-tls)).

### Database TLS

`DB_SSL` — not the URL's `sslmode` — is the single source of truth for the runtime connection.
`src/core/db/index.ts` strips `sslmode` before handing the URL to `pg`, because pg 8 reads that
parameter as *full certificate verification*, which fails against a managed instance reached by
IP. Prisma still reads the untouched URL, so keep `sslmode=require` in it for migrations.

| `DB_SSL` | Meaning |
|---|---|
| `disable` | plaintext — local docker only |
| `require` | encrypted, certificate not verified — current setting for the managed instance |
| `verify-full` | encrypted **and** verified against `DB_SSL_CA` — the only mode that stops a MITM |

### Migrations (Prisma 7)

Prisma 7 no longer accepts `url` inside `datasource`; it lives in `prisma.config.ts`, which also
loads `.env` via Node's built-in `loadEnvFile`. `prisma migrate dev` needs a *shadow database*
it can create and drop — a managed instance rarely allows that. Two options:

```bash
# A. local shadow DB (needs docker compose up)
SHADOW_DATABASE_URL=postgresql://app:app@localhost:5432/shadow npm run db:migrate -- --name <change>

# B. no shadow DB — diff the schema into a migration, then apply it
npx prisma migrate diff --from-migrations prisma/migrations --to-schema prisma/schema.prisma   --script --output prisma/migrations/<timestamp>_<change>/migration.sql
npm run db:deploy
```

> **Defaults must live in the database.** `@default(uuid())` and `@updatedAt` are Prisma *Client*
> behaviours, and this project never runs that client — so ids use
> `@default(dbgenerated("gen_random_uuid()"))` and `updatedAt` carries `@default(now())`. Follow
> the same rule for every model you add, or raw-SQL inserts will fail on NOT NULL.

### Protecting the docs

`/docs`, `/redoc`, `/openapi.json` and `/health` sit behind HTTP Basic auth as soon as
`DOCS_USERNAME` and `DOCS_PASSWORD` are set — a complete map of every endpoint and payload
shape is reconnaissance, so it should not be world-readable on a private service. Behaviour:

| | docs credentials set | not set |
|---|---|---|
| development | password prompt | open, with a startup warning |
| production | password prompt | **not mounted at all** |

The probes stay public on purpose: an orchestrator has no credentials, and `/status` is
deliberately reduced to `ok` / `error` per dependency so it leaks no hostnames or error strings.
`/health` is the detailed view, and it is gated.

> Basic auth only protects these operator pages. API routes use the JWT `requireAuth` guard.
> Both are meaningful only over HTTPS.

### Logs

One line per request, not a JSON dump of the whole request and response:

```
[13:13:23] INFO: GET /api/v1/users 200 12ms
[13:13:24] WARN: GET /health 401 1ms
[13:14:02] INFO: GET /api/v1/reports 200 812ms SLOW
```

`customSuccessMessage` in `core/http/app.ts` builds that line and the `req`/`res` serializers
drop the blobs; anything over `SLOW_REQUEST_MS` (300 ms) is tagged `SLOW` so a latency
regression is greppable. `/healthz` and `/readyz` are not logged at all. 4xx logs at `warn`,
5xx at `error`. Production emits structured JSON instead of the pretty line.

## Renaming this service

Nothing user-visible is hardcoded. Two environment variables drive every name — the landing
page, the `/health` dashboard, the Swagger and Redoc titles, the OpenAPI `info` block and the
Basic-auth realm:

```bash
SERVICE_NAME=Orbit Payments
SERVICE_DESCRIPTION=Ledger and settlement services.
```

`core/service.ts` reads those, derives the logo monogram from the initials (`Orbit Payments`
→ `OP`), and takes the version straight from `package.json` so it can never disagree with the
release. The Docker container name comes from the project directory, so it follows too.

The only file to edit by hand is `package.json` — set `name` to your service's slug. Then:

```bash
npm run dev    # the landing page already says Orbit Payments
```

## Layout

```
prisma.config.ts          Prisma 7 CLI config: datasource URL + migrations path
prisma/schema.prisma      DDL source of truth (no client generator)
prisma/migrations/        generated SQL migrations
src/
├─ core/                  infrastructure every feature reuses
│  ├─ config/             Zod-validated env → typed, frozen `config`
│  ├─ db/                 Kysely over a tuned pg Pool + pagination helpers
│  │  └─ types.ts         GENERATED by prisma-kysely — do not edit, do commit
│  ├─ http/               app factory, middleware chain, response envelopes,
│  │                      landing + /status + the /health dashboard
│  ├─ auth/               JWT issue/verify, argon2, requireAuth / requireRole / scope,
│  │                      plus Basic auth for the docs and ops pages
│  ├─ errors/             AppError hierarchy + Postgres error translation
│  ├─ logging/            pino + redaction
│  ├─ audit/              writeAudit(entry, trx)
│  ├─ storage/            Storage port + local-disk adapter
│  └─ docs/               OpenAPI registry + Swagger UI / Redoc mounting
├─ modules/               vertical slices — one folder per feature (see modules/README.md)
│  ├─ _template/          copy this to start a feature
│  └─ router.ts           the /api/v1 mount point
├─ shared/                API envelope, pagination, roles & scopes, the mounted-slice registry
└─ index.ts               bootstrap + graceful shutdown
tests/                    setup (migrations + truncate) and helpers (app, seedUser, authFor)
```

**Dependency direction is one-way**: `modules/` → `core/`/`shared/`, never the reverse
(ESLint enforces it; `core/http/app.ts` is the one composition-root exception). Slices never
import each other.

## Deploying

Google App Engine (Standard, Node.js 22) via Cloud Build. Cloud Build renders `app.yaml` from
Secret Manager at deploy time — no secret is committed, and `app.yaml` is gitignored.

```bash
gcloud builds submit --config cloudbuild.yaml --project=<PROJECT_ID>   --substitutions=_CLOUDSQL_INSTANCE=<proj>:<region>:<inst>,_CORS_ORIGINS=https://app.example.com
```

Full walkthrough — APIs to enable, secrets to create, IAM bindings, the Cloud SQL socket vs TCP
decision, and how to run migrations — is in **[DEPLOY.md](docs/DEPLOY.md)**. `app.example.yaml`
documents the shape Cloud Build renders to; never deploy it directly.

## The API contract

Two envelopes, everywhere:

```jsonc
{ "data": {}, "meta": { "nextCursor": null } }              // success
{ "error": { "code": "NOT_FOUND", "message": "..." } }      // failure
```

- Resource-oriented REST, plural nouns, under `/api/v1` → stable TanStack Query keys.
- **Mutations return the updated resource** so the client patches its cache instead of refetching.
- State transitions are action sub-resources (`POST /:id/approve`), not overloaded `PATCH`.
- Cursor pagination by default (`meta.nextCursor` → `useInfiniteQuery`); offset only for bounded
  admin grids.
- `error.code` is a stable contract the frontend switches on — 422 `VALIDATION_ERROR`,
  401 `UNAUTHENTICATED`, 403 `FORBIDDEN`, 404 `NOT_FOUND`, 409 domain codes.
- Every resource exposes `updatedAt` for optimistic concurrency.

## Performance rules for repositories

Dropping the ORM only pays off if the SQL is good:

- Compose **joins in a single statement** — killing N+1 is the whole point.
- `SELECT` only the columns you return; everything is parametrized (also the injection defense).
- One **index per access pattern**; enforce business uniqueness with DB constraints (unique /
  partial-unique), never an application check — that races.
- Wrap multi-write operations in a transaction, and write the audit row inside it.
- Pool tuning lives in `src/core/db/index.ts` (`max`, `statement_timeout`, idle timeout).

## Adding a feature

1. `cp -r src/modules/_template src/modules/<feature>` and rename the files.
2. Add its tables to `prisma/schema.prisma`; `npm run db:migrate -- --name <feature>`.
3. Fill in schema → repository → service → controller → routes → docs.
4. Register the router and the docs import in `src/modules/router.ts`.
5. Write the five test categories listed in `src/modules/_template/README.md`.
