# Mesa AI CTO — Frontend Boilerplate

> **Built by the MSL Team.**
> Next.js 16 (App Router, RSC, Turbopack) · React 19.2 + React Compiler ·
> TypeScript strict · Tailwind v4 · shadcn/ui · TanStack Query v5 · Zod 4 ·
> react-hook-form · self-issued JWT auth.

**This README is the contract.** If you are an AI agent (or a new engineer)
working in this repo, read it before writing a line of code. Every convention
below exists so the tenth feature costs what the first one did. When a change
doesn't fit these patterns, reconcile it with this document — do not invent a
parallel structure alongside it.

## ⚠️ Read this first: this is Next.js **16**

Next 16 has breaking changes versus most training data. Verify against
`node_modules/next/dist/docs/` before writing framework code. Known traps:

| Trap | Reality in Next 16 |
|---|---|
| `middleware.ts` | **Renamed to `proxy.ts`**, named export `proxy`, Node runtime (edge unsupported). Config flags dropped the `middleware` prefix. It lives at `src/proxy.ts`. |
| `cookies()` / `headers()` | **Async.** `const store = await cookies()`. |
| Route `params` | A **Promise**: `const { id } = await context.params`. |
| Bundler | **Turbopack** by default. |
| Memoization | React Compiler is **on** (`reactCompiler: true`). Do not hand-add `memo` / `useMemo` / `useCallback` for performance — only when profiling proves a need. |
| `setState` in `useEffect` | Lint **error** (`react-hooks/set-state-in-effect`). Use `useSyncExternalStore` for external state — see `src/hooks/use-mounted.ts` for the pattern. |

`AGENTS.md` in the repo root is regenerated by `next dev`; commit it with your
work rather than deleting it.

### Auth is OFF by default

`NEXT_PUBLIC_AUTH_ENABLED=false` ships as the default, which means:

- **every route is publicly reachable** — no redirect to login,
- you are signed in as `PREVIEW_USER` (`lib/auth/preview-user.ts`), so the
  sidebar, user menu, and role-gated controls all render.

Set it to `true` once a backend issues sessions. `proxy.ts` and `<AuthGate>`
already contain the full gate; the flag is the only thing to change.

> The dashboard, analytics, reports, and activity screens render **placeholder
> data** — they have no feature slice behind them yet. Each placeholder lists the
> exact steps to build it. The users table is wired to a real query hook and will
> show its error state until a backend answers at `NEXT_PUBLIC_API_BASE_URL`.

### Where does code go?

| Kind of code | Home |
|---|---|
| Fetching, mutations, validation, domain types | `features/<feature>/` |
| Anything a page renders that has domain meaning | `features/<feature>/components/` |
| Reusable widget with **no** domain knowledge | `components/shared/` |
| App-wide plumbing (api client, auth, env) | `lib/` |
| Shapes crossing features (entities, enums, transport) | `types/` |
| Page composition | `app/**/page.tsx` — **thin**, no fetching |
| Visual primitives | `components/ui/` (vendored — wrap, never edit) |

## The eight rules

**1. Server Components by default.** Add `'use client'` only for state, effects,
event handlers, browser APIs, Query hooks, forms, or context. Then push the
boundary to the smallest leaf: a Server page rendering a small client island
beats a whole-page `'use client'`. See `app/(auth)/login/page.tsx`.

**2. TanStack Query owns server state; `useState` owns UI state.** Never mirror
fetched data into local state. Never fetch in `useEffect`. Never fetch in a
component at all.

**3. One direction of flow.**
```
component → hook (useQuery/useMutation) → service (async fn) → api client → HTTP
```
Components never call services. Services never import React.

**4. `lib/api/client.ts` is the only thing that calls `fetch`.** It attaches the
bearer token, unwraps the `{ data, meta }` envelope, throws typed `ApiError`,
and does single-flight silent refresh on 401. (The one exception: server-side
Route Handlers, which use `app/api/_lib/backend.ts` — see that folder's README.)

**5. Query keys come from the factory.** `lib/api/query-keys.ts`, always. An
inline `['users']` breaks invalidation the moment someone else writes
`['users', 'list']`.

**6. Import through barrels, via `@/`.** `import { useUsers } from '@/features/users'` —
never `@/features/users/services/...`, never `../../../lib`. ESLint enforces both.

**7. Validate with Zod at every boundary.** Forms, Route Handler bodies, env.
One schema serves as both validator and type (`z.infer`) — never hand-write a
matching interface.

**8. Nothing in the frontend is a security boundary.** `proxy.ts`, `<AuthGate>`,
and `<RoleGuard>` are UX. The backend's RBAC is what protects data.

## Adding a feature — the recipe

Copy `src/features/users/` — it is the reference slice, deliberately complete.

1. **Model.** Add the entity to `types/models.ts`, any enum to `types/enums.ts`.
   Keep in lockstep with the backend schema.
2. **Endpoints.** Add paths to `lib/api/endpoints.ts`. Never inline a URL.
3. **Service.** `features/<f>/services/<f>.service.ts` — plain async functions on
   `api`, returning typed models. No React.
4. **Query keys.** Add a block to `lib/api/query-keys.ts` (`all` / `lists` /
   `list(params)` / `details` / `detail(id)`).
5. **Hooks.** `features/<f>/hooks/use-<f>.ts` — `useQuery` / `useMutation` over
   the service. Mutations write the returned resource into its detail cache,
   then invalidate the list namespace.
6. **Schemas.** `features/<f>/schemas.ts` — Zod for create/update, `z.infer` for
   the form types.
7. **Barrel.** Re-export the public hooks, components, and types from `index.ts`.
8. **Page.** `app/(app)/admin/<route>/page.tsx` — a Server Component composing
   `<PageHeader />` and a client island. Never add a sidebar or topbar to a page;
   the workspace layout already provides them.
9. **Nav.** Add the link to `lib/config/navigation.ts` and the path to
   `lib/constants.ts` `ROUTES`.
10. **States.** Every async surface owes the user three states besides success —
    use `LoadingState`, `EmptyState`, `ErrorState` from `components/shared/state-views`.

Then: `npm run check`.

## Auth model

```
login  → backend returns { accessToken, expiresIn, user }
                          + sets an httpOnly refresh cookie
access token  → memory only (lib/auth/token-store.ts)   ← never localStorage
refresh token → httpOnly cookie                          ← JS can never read it
401 on any request → single-flight refresh → retry once → else clear + redirect
page reload   → silent refresh restores the session
```

Why the access token is not in `localStorage`: anything there is readable by any
XSS payload and survives the tab. In memory it dies with the page, and the
httpOnly cookie restores the session on reload.

Three gates, none of them authorization (and the first two are inert until
`NEXT_PUBLIC_AUTH_ENABLED=true`):

| Layer | File | Purpose |
|---|---|---|
| `proxy.ts` | `src/proxy.ts` | Optimistic cookie check before render — no flash of a protected page |
| `<AuthGate>` | `components/shared/auth-gate.tsx` | Waits for silent refresh; redirects with `?next=` |
| `<RoleGuard>` | `components/shared/role-guard.tsx` | Hides UI a role shouldn't see |

## The API layer, twice

There are **two** API clients and mixing them is a bug:

- `@/lib/api/client` — runs in the **browser**. In-memory token, silent refresh,
  public base URL. Used by feature services.
- `@/app/api/_lib/backend` — runs on the **server**, inside Route Handlers only.
  Request cookies, private hostname, may hold secrets.

`src/app/api/` holds our own Route Handlers (health check, first-party auth
cookie, optional transparent proxy). **Read `src/app/api/README.md` before
adding one** — most data does not belong there, and every hop costs latency.

## The app shell

`components/layout/app-shell.tsx` pins the sidebar and topbar to the viewport
and scrolls **only** the main content, inside a `ScrollArea`. Two details do all
the work and are easy to lose in a refactor:

- `h-svh overflow-hidden` on the `SidebarProvider` pins the chrome.
- **`min-h-0`** on every scrolling flex child (`SidebarInset` and the
  `ScrollArea`). Without it a flex child grows to its content height, the whole
  page scrolls, and the sidebar/topbar scroll away with it. This is *the*
  classic app-shell bug.

Other shell rules:

- **Pages render as `children`.** Never add a second sidebar or topbar inside a page.
- **Container queries, not viewport breakpoints.** `main` is `@container/main`,
  so page grids use `@xl/main:` / `@4xl/main:` and reflow when the *sidebar*
  collapses — something `md:` / `lg:` cannot see. (Viewport breakpoints are still
  right for the landing and auth screens, which sit outside the shell.)
- **One nav config, role-filtered.** `lib/config/navigation.ts` drives the
  sidebar tabs *and* the topbar breadcrumb, so they can never disagree.
- **Workspace accents rebind on the wrapper.** `<AppShell workspace="admin">`
  applies `.theme-admin`, which rebinds `--primary` / `--sidebar-primary` /
  `--ring`. Everything downstream reads those variables, so adding a second
  workspace is a CSS class plus a nav filter — with zero per-component branching.
- **No `backdrop-blur` on the topbar.** A `backdrop-filter` ancestor creates a
  containing block that traps `position: fixed` descendants, breaking dialogs
  and drawers opened from it.

## Styling & branding

- **Poppins** is the global typeface, self-hosted by `next/font` in
  `app/layout.tsx` as `--font-poppins`, bound to Tailwind's `--font-sans` and
  `--font-heading` in `globals.css`. Change the font in `layout.tsx` only.
- **Brand colours** are the `--primary` / `--sidebar-*` / `--chart-*` tokens in
  `globals.css` (`:root` and `.dark`). Never hardcode a colour in a component.
- **Brand marks** live in `components/layout/brand.tsx` — `<BrandMark />`,
  `<Brand />`, `<BuiltByMsl />`. Rebrand there, once.
- **Light is the default and the canonical look**; dark is fully supported and
  reachable from the theme toggle (or by choosing "System"). Design light first,
  then check dark — every surface is `bg-background` / `bg-card`, with the accent
  restricted to buttons, active nav, focus rings, and small `bg-primary/10`
  chips. There are deliberately **no** decorative gradient utilities: a wash
  that reads well in light almost always muddies dark.
- `components/ui/*` is vendored by the shadcn CLI. To change a primitive, wrap
  it in `components/shared/`; editing it directly is lost on the next update.

> This project uses the **base-ui** shadcn style: composition uses a `render`
> prop, **not** `asChild`. E.g. `<Button render={<Link href="/x" />}>`.

## Do / Don't

**Do** — thin pages · services React-free · Query hooks for all server state ·
keys from the factory · Zod at boundaries · `@/` imports through barrels ·
loading/empty/error states on every async surface · `notify.*` for toasts ·
`logger.*` instead of `console`.

**Don't** — `fetch` in a component · inline query-key strings · reach past a
feature barrel · mirror server data in `useState` · fetch in `useEffect` ·
hand-edit `components/ui/*` · add axios or a second HTTP path · hardcode a URL,
colour, or route string · put a secret in a `NEXT_PUBLIC_*` var · treat any
frontend check as authorization.
